#+TITLE: Hammerspoon 2: what is missing
#+AUTHOR: Daniel M. German
#+DATE: 2026-08-31

Capabilities that Hammerspoon 1 had and Hammerspoon 2 still does not, found while porting the
Hammerspoon 1 configuration. Each entry says what it blocks here and what is done instead.

*Last checked on 2026-10-24*, against the debug build at =a394e6b8=, which is upstream
=f69f9a3e= plus three local commits (=hs.socket=, =exit= and =quit= in =hs2=, and a
Makefile). Everything else this file once listed has been fixed upstream or no longer
matters to this configuration, and has been removed.

* Summary

| Finding                            | Blocks | Worked around       |
|------------------------------------+--------+---------------------|
| No window lookup by identifier     | No     | Yes, filter windows |
| One Spoon directory, no search path | No     | No                  |
| Command line client has no =-c=     | No     | Yes, standard input |

* No window lookup by identifier

Hammerspoon 1 had =hs.window.get(id)=. =hs.window= offers =focusedWindow=, =allWindows=,
=visibleWindows=, =windowsForApp=, =windowsOnScreen=, =windowAtPoint= and
=orderedWindows=, but nothing that finds a window by its identifier, although =HSWindow.id=
exists.

*Workaround*: filter =allWindows()=. The edit-with-Emacs round trip in =hs_emacs-gt= needs
this, because it identifies the window it must paste into by its id.

* One Spoon directory, and no search path

=hs.loadSpoon(name)= loads =<configDir>/Spoons/<name>/init.js= and looks nowhere else.

*Blocks*: keeping Spoons that are specific to this machine apart from generic ones that
could be published.

*Wanted*: a list of directories to search.

=hs.loadSpoon= also returns a cached module, so an edit to a Spoon has no effect until
=hs.reload()=. That is reasonable, but worth knowing while developing a Spoon.

* The command line client has no -c option

Hammerspoon 1's =hs -c "code"= was how Emacs called back into Hammerspoon. The Hammerspoon
2 client, =hs2=, reads code from standard input instead. Its only options are
=--log-level=, =--no-prompt=, =--version= and =--help=.

*Workaround*: pipe the code in. From elisp, =call-process-region= sends the code as the
region, with =--no-prompt= as the argument.

The client evaluates each line of its input separately. A line can hold several statements
and a trailing =//= comment, but a =const= declared on one line is not visible on the next.

The client and the application must also be the same build. An out-of-date client fails with
=Connection to Hammerspoon 2 was lost= for every input, including =1+1=. That reads as
Hammerspoon 2 being down rather than as a version mismatch.
