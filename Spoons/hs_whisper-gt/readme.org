* hs_whisper-gt

Dictation with a local Whisper. Press a key, speak, press it again, and the text is typed
into whatever had focus — or put on the clipboard, if that is the key you pressed.

Everything runs on this machine. The audio is never sent anywhere; only a filter can send
the text anywhere, and only one you configured yourself.

This is a port of the Hammerspoon 1 /hs_whisperDictation/ spoon to Hammerspoon 2 and
JavaScript.

* Simple usage

#+begin_src js   :exports both
const whisper = hs.loadSpoon("hs_whisper-gt")

whisper.config.languages = ["en"]
whisper.config.recorder = "sox"
whisper.config.transcriber = "whisperkit"

whisper.bindHotkeys({
    transcribeToggle:            [["cmd", "ctrl"], "return"],
    transcribeToClipboardToggle: [["cmd", "ctrl", "alt"], "return"],
    languageSelect:              [["cmd", "ctrl", "alt"], ";"]
})

whisper.start()
#+end_src

Install what that needs with =brew install sox whisperkit-cli=.

=transcribeToggle= types the text into whatever had focus. =transcribeToClipboardToggle=
puts it on the clipboard instead, to be pasted wherever you want it. Both start and stop the
same way: press once to begin, press again to transcribe what was said.

A =🎤 (en)= item appears in the menu bar. While recording it counts the seconds, and while
transcribing it shows =⏳=.

* The menu bar item

A left click on it does what the =transcribeToggle= key does. It starts a dictation into
whatever has focus, and a second left click stops it and types the text. While a dictation
is being transcribed, a left click only reports that it is busy.

A right click, or a Ctrl-click, opens a menu containing everything the Spoon can do, so
nothing is reachable only by a keyboard shortcut you have to remember:

- *Dictate* and *Dictate to the clipboard* while idle; *Stop and transcribe* and *Abort*
  while one is running
- *Language*, with the current one ticked
- *Filter*, with the active one ticked and /No filter/ to clear it
- *Dictate to <processor>*, while idle, when a processor is configured
- *Processor*, choosing which processor that entry and =transcribeToProcessorToggle= use
- *Paste each chunk as it is ready*, ticked when it is on. It is shown only with the
  =streaming= recorder; see /Pasting each chunk as it is ready/
- *Microphone*, titled with the input device being recorded from, with /Automatic/ and every
  input device to choose from. When the device is not the system default and was not chosen
  by name, the title says why: either the default is a Bluetooth headset (see /Which
  microphone is used, and Bluetooth headsets/), or the default changed during a dictation and
  the streaming server has not restarted yet
- *Transcribe a recording again…*
- *Diagnostics*: show the diagnostics, turn detailed logging on, restart the streaming
  server, forget old recordings
- a last line naming the recorder and transcriber actually in use, so a fallback is visible

The menu is rebuilt each time it opens, so it shows the current state. Entries that would do
nothing are greyed out rather than hidden. The language cannot be changed part way through a
dictation, because it is fixed when the dictation starts. Nor can the microphone, because
changing it restarts the streaming server, which would discard the recording. The filter can
be changed, and applies to the dictation in progress, because it runs on the finished text.
The processor is fixed when a dictation to it starts, so changing it applies to the next one.

With =config.monitorUserActivity=, a click during a recording normally stops the text from
being pasted. A click on this menu bar item does not count, so a left click can stop a
dictation and still have the text pasted.

This needs a Hammerspoon 2 built from 9ea05e03 or later, which is when a menu bar item began
reporting which button was clicked (issue #272).

** Microphone permission

Hammerspoon 2 needs microphone permission, in *System Settings → Privacy & Security →
Microphone*. Without it macOS does not refuse to record: it returns samples that have been
replaced with zero, with no error of any kind, and the only symptom is that nothing is ever
transcribed. So the Spoon checks the permission before it records and says so rather
than recording silence.

That applies to the =sox= recorder, which records inside Hammerspoon. The =streaming=
recorder's server is a separate process started by launchd, so it is Python that needs the
permission, not Hammerspoon. The server reports a microphone it cannot open as an error on
the first recording; see /The streaming server/ below.

=config.monitorUserActivity= additionally needs *Accessibility*, because it watches for
typing with an event tap. Without it the Spoon still dictates; it just cannot tell whether
you moved on while it was recording, so it will not guard auto-paste.

* Recording and transcribing

Two recorders and three transcribers, each chosen by name.

** Recorders

| Name        | What it does                                           | When to use it            |
|-------------+--------------------------------------------------------+---------------------------|
| =sox=       | Records one file for the whole session                 | Simple and reliable       |
| =streaming= | A Python server with voice-activity detection, cutting | Long dictations: the text |
|             | the audio at pauses and handing over each chunk        | starts arriving sooner    |

=sox= needs =brew install sox=.

*** Which microphone is used, and Bluetooth headsets

Both recorders record from the system default input, with one exception: when the default
input is a Bluetooth headset, such as AirPods, they record from the Mac's built-in
microphone instead. The headset then only plays sound, and you can keep listening to it while
you dictate.

This is necessary because a Bluetooth headset cannot play sound well and use its microphone
at the same time:

1. A headset plays sound using a Bluetooth profile called A2DP. A2DP sends high-quality
   audio, but only from the Mac to the headset.
2. Its microphone works only with a second profile, HFP. HFP sends audio in both directions,
   but at the quality of a telephone call.
3. The headset uses one profile at a time, and stays on HFP for as long as anything has its
   microphone open.

This is a limitation of Bluetooth and macOS, not of Hammerspoon 2 or of this Spoon. With
AirPods on macOS 26, the sound did not just lose quality when their microphone was opened. It
stopped completely, and started again only when the microphone was closed. Recording with sox
stopped the sound in the same way as the streaming server, so it does not depend on the
recorder.

It matters more for the =streaming= recorder, because its server keeps the microphone open
for =--microphone-idle-timeout= seconds (five minutes) after each dictation, so that the
next one starts without waiting for the device. Recording from the AirPods would stop their
sound for that long after every dictation.

macOS usually makes AirPods the default input as well as the default output when they
connect. Without =bluetoothInputAvoid=, the sound in the AirPods would stop as soon as they
connected.

How the device is chosen:

1. A device chosen from the *Microphone* menu, or with =inputDeviceSet()=, is used while it
   is connected. When it is disconnected, the rules below apply until it is connected again.
2. Otherwise, a device named in =soxAudioInputDevice= or =streamingAudioInputDevice= is used
   as it is.
3. Otherwise, if the default input is a Bluetooth device and =bluetoothInputAvoid= is =true=
   (the default), the built-in microphone is used.
4. Otherwise the default input is used. This includes a Mac with no built-in microphone,
   where the headset's microphone is the only one available.

The device is chosen afresh for every recording and sent with it, so a change of default
input, or a choice from the menu, applies from the next dictation. Nothing restarts. The
server reopens the microphone when a recording names a different device from the one it has
open. =diagnose()= reports the device the next recording will use, and the one the server
has open.

To dictate into the headset instead, set =bluetoothInputAvoid: false=. Its sound will then
stop, or play at telephone quality, while the microphone is open.

*** Chunking

=streaming= watches for pauses and cuts the recording at them, so a long dictation becomes
several chunks instead of one. Each chunk is sent to the transcriber as soon as it is cut,
while you carry on speaking, and the results are joined in order at the end. This is what
makes =whisperserver= worth running: the model is already in memory, so a sentence comes
back while you are still saying the next one, rather than everything being transcribed after
you stop.

Each chunk's text is shown as it arrives, and the menu bar counts them —
=⏳ 2/3 (en)= means two of three chunks are done. A dictation short enough to produce a
single chunk shows no per-chunk text, because it would only repeat what is about to be
typed or copied.

#+begin_src js   :exports both
whisper.config.streamingSilenceThreshold = 3.0   // seconds of silence that ends a chunk
whisper.config.streamingMinChunkDuration = 5.0   // never cut a chunk shorter than this
whisper.config.streamingMaxChunkDuration = 600.0 // cut anyway after this long
whisper.config.chunkAlertSeconds = 3             // how long each chunk's text is shown, 0 for none
#+end_src

A pause only ends a chunk if it is longer than =streamingSilenceThreshold= /and/ the chunk
so far is longer than =streamingMinChunkDuration=. With the values above, pausing for two
seconds between sentences will not split them, and neither will a pause four seconds in.
Lower both if you want the text to come back in smaller pieces.

**** Pasting each chunk as it is ready

When a dictation is being pasted (=transcribeToggle=, or a left click on the menu bar item),
each chunk is pasted as soon as it has been transcribed, while you carry on speaking. You do
not have to wait for the end of the dictation. Chunks are pasted in the order they were
recorded. A chunk that comes back early waits for the ones before it. A chunk that cannot be
transcribed is skipped and reported, as it is at the end. Consecutive chunks are separated
by a blank line.

#+begin_src js   :exports both
whisper.config.streamingChunkInsert = true   // false to paste the whole dictation at the end
#+end_src

It can also be turned on and off from the menu bar item, or with =chunkInsertToggle()=. That
change lasts until the configuration is reloaded. A dictation already in progress keeps the
setting it started with.

It does not apply in three cases, which all fall back to delivering the whole text at the
end:

1. The dictation goes to the clipboard, or to a callback, rather than being pasted.
2. A filter is active. A filter runs over the whole text, and pasting chunk by chunk would
   either bypass it or run it over fragments.
3. No window had focus when the dictation started.

Each chunk is pasted only into the window that had focus when the dictation started. If
focus is somewhere else when a chunk is ready, pasting stops for the rest of the dictation.
With =config.monitorUserActivity= it also stops once you type or click, as auto-paste does;
the Spoon's own paste keystrokes are not counted. When the dictation ends, the chunks that
were not pasted are put on the clipboard, so ⌘V back in the original window completes it.
When every chunk was pasted, the clipboard holds the whole dictation.

The per-chunk text shown by =chunkAlertSeconds= is not shown for a chunk that is pasted,
because it would only repeat what has just appeared in the application.

**** Chunks without speech

A pause long enough to end a chunk can produce a chunk with no speech in it at all, most
often at the end, when you stop dictating and then press the key. Whisper given such a chunk
tends to invent text for it, typically "Thank you.", which would be pasted or handed to a
processor. The server's voice-activity detector reports whether it found speech anywhere in
each chunk, and a chunk without speech is not transcribed.

#+begin_src js   :exports both
whisper.config.streamingSilentChunkSkip = false   // transcribe every chunk anyway
#+end_src

The audio is still saved, so =transcribeAgain= can still be used on the whole recording.

=sox= does not chunk: it records one file and transcribes it once you stop.

*** The streaming server

=whisper_stream.py= is a server of its own, started by launchd rather than by the Spoon,
and the Spoon connects to it over a WebSocket on =config.streamingUrl=
(=ws://127.0.0.1:12341=). Running it separately does three things:

1. Emacs, or anything else that speaks the protocol below, can use the same server. One
   client is served at a time; a new connection takes over from an old one, whose recording
   ends and is kept.
2. The voice-activity model stays loaded across Hammerspoon reloads, instead of being
   loaded again by every reload.
3. The microphone is open only around dictation. The server opens it when a recording
   starts and closes it once it has gone =--microphone-idle-timeout= seconds (300) without
   one, so the first dictation after a pause waits for the device to open and the ones after
   it do not. Measured on 2026-10-15: the built-in microphone opened in 0.03 s.

It needs =pip install numpy sounddevice scipy torch torchaudio websockets= in the Python that
the LaunchAgent runs, =~/.config/dmg/python/bin/python3=:

#+begin_src sh   :exports both
~/.config/dmg/python/bin/python3 whisper_stream.py --check-deps
#+end_src

The LaunchAgent is =launchd/org.turingmachine.whisper-stream.plist=. Install it once:

#+begin_src sh   :exports both
cp launchd/org.turingmachine.whisper-stream.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/org.turingmachine.whisper-stream.plist
#+end_src

After changing =whisper_stream.py=, restart it, which is what =serverRestart()= and the menu
item do:

#+begin_src sh   :exports both
launchctl kickstart -k gui/$(id -u)/org.turingmachine.whisper-stream
#+end_src

Its log is =~/Library/Logs/whisper-stream.log=: connections, recordings, and when the
microphone opens and closes.

The first recording asks macOS for microphone permission for Python, because the server is
not a child of Hammerspoon. If no prompt appears, grant it in *System Settings → Privacy &
Security → Microphone*.

**** The protocol

Each message is one JSON object in one WebSocket text frame.

From the client:

| Command                | Fields, all optional                                                     |
|------------------------+--------------------------------------------------------------------------|
| =start_recording=      | =filename_prefix=, =output_dir=, =audio_input= (device name, =null= for the default), =silence_threshold=, =min_chunk_duration=, =max_chunk_duration=, =perfect_silence_duration= |
| =stop_recording=       |                                                                          |
| =status=               |                                                                          |

Settings left out of =start_recording= take the server's defaults, not the previous
recording's.

From the server:

| Event               | Fields                                               | When                                         |
|---------------------+------------------------------------------------------+----------------------------------------------|
| =server_ready=      | =recording=, =microphone_open=, =device=, =test_file= | on connecting                                |
| =status=            | the same                                             | in answer to =status=                        |
| =recording_started= | =device=                                             | once the microphone is open and recording    |
| =chunk_ready=       | =chunk_num=, =audio_file=, =is_final=, =peak=, =speech= | each chunk cut at a pause, and any audio left at the end |
| =complete_file=     | =file_path=                                          | at the end, before the final chunk           |
| =recording_stopped= |                                                      | at the end, after everything else            |
| =silence_warning=   | =message=                                            | the microphone delivers nothing at all       |
| =error=             | =error=                                              | anything that failed, including a microphone that would not open |

A failed =start_recording= is answered with =error= and then =recording_stopped=, and no
=recording_started=.

=speech= says whether the voice-activity detector found speech anywhere in the chunk.
Whisper given a chunk without speech tends to invent text for it, such as "Thank you.", so a
client can skip such a chunk; the Spoon does, with =streamingSilentChunkSkip=. The file is
written either way.

The chunk with =is_final= set is sent only when audio is left over after the last cut. When
the recording stops just after a cut there is no final chunk, so the end of a recording is
=recording_stopped=, not a final chunk.

** Transcribers

| Name            | What it is                       | Speed  | Best for                       |
|-----------------+----------------------------------+--------+--------------------------------|
| =whisperkit=    | whisperkit-cli, on the Apple     | Fast   | Apple Silicon                  |
|                 | Neural Engine                    |        |                                |
| =whispercli=    | whisper.cpp's whisper-cli, on    | Slower | Any Mac                        |
|                 | CPU or GPU                       |        |                                |
| =whisperserver= | A local whisper.cpp HTTP server  | Fast   | Dictating often: the model     |
|                 | with the model already in memory |        | stays loaded between sessions  |

#+begin_src sh   :exports both
brew install whisperkit-cli          # whisperkit
brew install whisper-cpp             # whispercli, plus a model to point at
#+end_src

=whisperserver= talks to a server that is already running. Set =whisperserverCmd= and
=whisperserverModelPath= as well and the Spoon will start one when nothing answers, and stop
it again when the Spoon stops.

** Falling back

A recorder or transcriber that cannot be used does not leave the Spoon unusable. =streaming=
falls back to =sox=, and =whisperkit= and =whisperserver= fall back to =whispercli=. The
fallback is reported, so it is clear which one is actually in use; =whisper-diagnose= also
says.

* Filters

A filter passes the transcription through something before it reaches the clipboard: fix the
grammar, translate it, make a list of it, answer it.

#+begin_src js   :exports both
whisper.config.filters = [
    {name: "Fix grammar", abbrev: "CLN", cmd: "~/bin/llm/query-model.py filter -p 'Correct the grammar, answering with the corrected text only'"},
    {name: "Answer it",   abbrev: "ANS", cmd: "~/bin/llm/query-model.py answer"},
    {name: "Trim spaces",                fn: (text) => text.replace(/\s+$/, "")}
]

whisper.bindHotkeys({filterSelect: [["cmd", "ctrl", "alt"], "f"]})
#+end_src

Each entry needs =name= and either:

- =cmd= — a shell command reading the text on its standard input and writing the result to
  its standard output. It runs under =/bin/zsh -l=, so the PATH is the one you would have at
  a prompt.
- =fn= — a function taking the text and returning the replacement.

=fn= wins if an entry has both. =abbrev= is optional and is shown in the menu bar while that
filter is active, as =🎤 (en) [CLN]=.

=filterSelect= opens the chooser; the filter chosen there stays active for every later
dictation until it is changed, and /No Filter/ clears it.

A filter that fails — no such command, a non-zero exit, no output, a function that throws or
returns something that is not a string — is reported and the unfiltered text is used
instead. Losing a dictation because a grammar filter broke would be the worse failure.

A filter is the one part of this Spoon that can send your words off the machine. One calling
a cloud API sends every dictation you pass through it to that service.

* Processors

A processor is how a dictation issues a command instead of producing text. It is handed the
transcription and is responsible for whatever is done with it. Nothing is pasted or copied.

A dictation goes to a processor only when it is started with its own key,
=transcribeToProcessorToggle=. The other keys go on producing text.

#+begin_src js   :exports both
whisper.config.processors = [
    {name: "Speak it", abbrev: "SAY", cmd: "say"},
    {name: "Log it",   abbrev: "LOG", fn: (text, details) => {
        hs.fs.append("/tmp/dictations.txt", `${details.lang}: ${text}\n`)
        return "logged"
    }}
]

whisper.bindHotkeys({
    transcribeToProcessorToggle: [["cmd", "ctrl", "alt", "shift"], "return"],
    processorSelect:             [["cmd", "ctrl", "alt"], "p"]
})
#+end_src

Each entry needs =name= and either:

- =cmd= — a shell command reading the text on its standard input. It runs under =/bin/zsh -l=,
  like a filter, with =WHISPER_LANG= set to the dictation's language and =WHISPER_CHUNK= to
  the chunk's number when it is given one chunk.
- =fn= — a function called as =fn(text, details)=, where =details= is ={lang, chunk}=. It may
  return a promise.

The first processor in the list is used until another is chosen with =processorSelect=,
=processorSet= or the menu. The choice lasts until the configuration is reloaded. It is fixed
when a dictation starts, so changing it applies to the next dictation. While a dictation to
a processor is recording, the processor's =abbrev= is shown in the menu bar, in place of the
filter's. The filter is not applied to that dictation.

When the processor has finished, a message says so: =Sent to 'Log it': logged=. Whatever
the command printed, or whatever the function returned, follows the colon. When it has
nothing to say, the message is just =Sent to 'Log it'=. A command that exits with a
non-zero status, or a function that throws, is reported as an error with the first line of
its standard error. The menu bar shows the transcribing icon until the processor has
finished.

With the =streaming= recorder, a processor is called once for each chunk (see /Chunking/).
Each chunk is handed over as soon as it, and every chunk before it, has been transcribed, so
the processor can act while you are still speaking. Chunks are handed over one at a time and
in the order they were spoken: the next chunk waits until the processor has finished with
the one before. A chunk that cannot be transcribed is skipped and reported. Each call is
reported separately, as =Sent to 'Log it' (chunk 2): logged=. A =cmd= also has the
chunk's number, counting from 1, in =WHISPER_CHUNK=, and an =fn= has it as =details.chunk=.

With =sox= there is only one chunk, so the processor is given the whole dictation once it
ends, and =WHISPER_CHUNK= is not set.

* Where the text goes

Two bindings over the same recording, differing only in what happens to the transcription:

#+begin_src js   :exports both
whisper.config.monitorUserActivity = true

whisper.bindHotkeys({
    transcribeToggle:            [["cmd", "ctrl"], "return"],        // type it
    transcribeToClipboardToggle: [["cmd", "ctrl", "alt"], "return"]  // copy it
})
#+end_src

=transcribeToggle= writes the text into the application that had focus when you started, by
sending the paste keystroke. =transcribeToClipboardToggle= puts it on the clipboard and
stops there.

With =monitorUserActivity= the typing is abandoned, and the text left on the clipboard
instead, if while recording you typed =config.activityKeyLimit= keys or more, clicked
anything, or changed application — on the assumption that you are now doing something else
and do not want text appearing under the cursor. This needs Accessibility permission, as
above; without it the text still arrives, it is just not guarded.

=config.pasteWithEmacsYank= types into Emacs with =ctrl-y= rather than =⌘V=.

* Methods

Every method returns the Spoon, so calls can be chained.

** transcribeToggle(callbackOrPaste)

Start recording, or stop and transcribe if already recording.

Called with nothing, the transcription goes to the clipboard. Pass =true= to have it typed
into the application that had focus instead, or a function to be given the text, in which
case neither happens:

#+begin_src js   :exports both
whisper.transcribeToggle()                                  // to the clipboard
whisper.transcribeToggle(true)                              // typed where the cursor is
whisper.transcribeToggle((text) => console.log(text))       // to your own code
#+end_src

The two hotkey actions, =transcribeToggle= and =transcribeToClipboardToggle=, are the second
and first of these.

** transcribeBegin(callbackOrPaste) / transcribeEnd()

The two halves of the toggle, for binding a key that records while it is held.

** transcribeAbort()

Abandon the recording or transcription in progress and go back to idle, leaving the
clipboard alone. Does nothing when idle.

** transcribeAgain(callback)

Offer the recent recordings and transcribe the chosen one again — for a dictation that came
back wrong, to try another language or another transcriber without saying it all again.

=config.retranscribeCount= is how many are offered. =config.retranscribeTranscriber= names
one to use instead of the current one, or =null= for the current one.

** recordingTranscribe(audioFile, callback)

Transcribe one named recording, without the chooser.

** languageGet() / languageSet(lang) / languageSelect() / languageNext()

The language being asked for, which must be one of =config.languages=. =languageSelect=
opens a chooser; =languageNext= moves through the list.

#+begin_src js   :exports both
whisper.config.languages = ["en", "ja", "es"]
whisper.languageSet("ja")
#+end_src

** inputDeviceSet(name)

Record from the input device called =name=, as =hs.audiodevice= reports it, or choose
automatically when =name= is =null=. It does the same as the *Microphone* menu, and applies
from the next recording. It is refused during a dictation, so that what the menu shows is
what is being recorded. The choice lasts until the configuration is reloaded; to keep a
device permanently, set =soxAudioInputDevice= or =streamingAudioInputDevice=.

#+begin_src js   :exports both
whisper.inputDeviceSet("MacBook Pro Microphone")
whisper.inputDeviceSet(null)
#+end_src

** filterSelect()

Open the filter chooser; see /Filters/ above.

** chunkInsertToggle() / chunkInsertSet(enable)

Turn pasting each chunk as it is ready on or off; see /Pasting each chunk as it is ready/.
Both set =config.streamingChunkInsert=, and the change lasts until the configuration is
reloaded.

** transcribeToProcessorToggle()

Start a dictation that goes to the selected processor, or stop the one in progress; see
/Processors/ above. It is =transcribeToggle("processor")=.

** processorSelect() / processorGet() / processorSet(which)

Open the processor chooser, return the selected processor (null when none is configured),
or choose one by =name= or index; see /Processors/ above.

** recordingsList() / recordingsPrune()

The recordings in =config.tempDir=, newest first, and a prune down to the newest
=config.recordingsKeep= of them. Pruning also happens at =start()=. Set =recordingsKeep= to
=0= to keep every recording ever made, as version 1 did.

** debugSet(enable) / serverRestart() / diagnose()

=debugSet(true)= logs in detail. =serverRestart()= asks launchd to restart the streaming
server and connects to the new one, for a server that has got stuck; it is refused during a
dictation. =diagnose()= prints a snapshot — state, the backends actually in use, the session,
the streaming server's connection and what it has open, the input device, both permissions,
how many recordings there are — to the console.

#+begin_src js   :exports both
whisper.debugSet(true)
whisper.serverRestart()
whisper.diagnose()
#+end_src

** isRecording() / state()

Whether a recording is in progress, and the state machine's state: =IDLE=, =RECORDING=,
=TRANSCRIBING= or =ERROR=.

** bindHotkeys(mapping) / start() / stop()

=bindHotkeys= takes any of =transcribeToggle=, =transcribeToClipboardToggle=,
=transcribeToProcessorToggle=, =languageSelect=, =languageNext=, =filterSelect=,
=processorSelect=, =chunkInsertToggle=, =transcribeAgain= and =transcribeAbort=, each
holding =[[modifiers], key]=. All are optional. =transcribeToggle= and
=transcribeToClipboardToggle= both call =transcribeToggle()=, with and without the argument
that says to type the text.

=start()= puts the menu bar item up and returns at once; the recorder and transcriber are
chosen in the background, because checking them means running commands and none of that may
block Hammerspoon. A key pressed in that window is answered rather than ignored.

All on =config=.

retranscribeTranscriber: null

#+end_src

=bluetoothInputAvoid= records from the built-in microphone when the default input is a
Bluetooth headset, so that the headset keeps playing sound. See /Which microphone is used,
and Bluetooth headsets/.

A setting is one key, never a nested object, because =hs_interactive-gt='s =use()= applies
=config= with =Object.assign=. That is a shallow merge, so setting one key of a nested
object would silently replace the whole object and discard every other default in it.

* Troubleshooting

Start with =whisper-diagnose=, or =whisper.diagnose()=. It reports both permissions, which
backends are actually in use rather than which were asked for, and whether any task or timer
is being leaked.

** Nothing is transcribed, and there is no error

Almost always microphone permission; see above. =diagnose()= reports it. A recording that
really is silent is caught before it is transcribed, with a message naming the input device
and saying which of the two causes the amplitude points at.

** The microphone is connected but delivers silence

In order, least invasive first:

1. Unplug the microphone and plug it back in. On macOS 26 a USB audio device can get into a
   state where it enumerates but delivers silence to some clients — notably Python's
   =sounddevice=, through PortAudio — and a physical replug clears it.
2. =sudo killall corespeechd=, which restarts the speech-recognition daemon.
3. =sudo killall coreaudiod=, which resets system-wide audio. Every application using audio
   is interrupted briefly, so only if the first two did not help.

** Sound in AirPods or another Bluetooth headset stops

Something has their microphone open, and they have switched to the headset profile. See
/Which microphone is used, and Bluetooth headsets/. Run =diagnose()=:

- If the streaming server's device is the headset, =bluetoothInputAvoid= is =false=, or a
  recorder's device is set to the headset in the configuration.
- If it is the built-in microphone, another application has the headset's microphone open.
  Quit it or change its input.

The sound starts again once the microphone is closed. =whisper.stop()= closes it. Changing
the default input in *System Settings → Sound* also closes it, because the server restarts.

** The streaming server cannot be reached

=whisper-diagnose= says whether the Spoon is connected. If it is not:

#+begin_src sh   :exports both
launchctl print gui/$(id -u)/org.turingmachine.whisper-stream | grep -E 'state|pid'
tail ~/Library/Logs/whisper-stream.log
~/.config/dmg/python/bin/python3 whisper_stream.py --check-deps
#+end_src

The log's first line after a start is ={"status": "listening", "port": 12341, ...}=, written
once the model has loaded. A server that never gets there has failed to load its model or
to take the port, and the log says which.

** A recording fails with "The microphone did not open"

The server gives up on the microphone after =--microphone-open-timeout= seconds (10) rather
than hanging, because macOS and PortAudio do not fail when a process has no microphone
permission: the open simply never returns. The usual cause is that Python has no microphone
permission. The server goes on answering, and the next recording tries again.

** A command cannot be found

#+begin_src sh   :exports both
brew install sox whisperkit-cli whisper-cpp
#+end_src

Or set the =...Cmd= setting to where it actually is. A bare name is looked up on the PATH of
a login shell; a path beginning with =/= is used as given.

** Watching a dictation go through

#+begin_src js   :exports both
whisper.debugSet(true)
#+end_src

Then dictate and watch the console: each chunk with its file, size and peak amplitude, and
each transcriber invocation and what it returned. The streaming server's side is in
=~/Library/Logs/whisper-stream.log=; for its audio levels about once a second, add
=--verbose= to the LaunchAgent's arguments and restart it.

* Differences from the Hammerspoon 1 spoon

Behaviour that deliberately changed, beyond names and the language:

- *Transcription no longer blocks Hammerspoon.* Version 1 deferred a blocking read by 10 ms
  and called it asynchronous, so everything froze for the length of every transcription.
- *A chunk that cannot be transcribed is reported, not pasted.* Version 1 wrote
  ="[chunk 3: error - ...]"= in among the words, so the error reached the clipboard and from
  there whatever you pasted into. Now only the chunks that worked are joined, and the loss
  is reported.
- *The silent-recording check applies to both recorders.* It needs the peak amplitude, which
  only the streaming recorder reported, so with =sox= it never ran at all. The =sox= recorder
  now measures it, and the microphone permission is checked before recording either way.
- *Recordings are pruned.* Nothing in version 1 ever deleted one, so =tempDir= held every
  recording ever made.
- *Each recording names its own files.* The streaming server was told a filename prefix once,
  when it started, which was =warmup=: every later recording was named after the warmup, and
  each session's chunks overwrote the previous session's. The prefix now goes with each
  recording and carries the language and the time.
- *=sox= is waited for rather than guessed at.* Version 1 terminated it and read the file
  0.1 seconds later whether or not it had finished writing it.
- *The transcribers' error output is kept out of the text.* Every command ended =2>&1= in
  version 1, so a warning from the tool became part of the transcription.
- *Paths are not pasted into shell strings.* Arguments go as a list, so a path containing a
  quote cannot break the command.
- =diagnose()= *works.* In version 1 it called a function that does not exist, and so failed
  every time it was called.
- *The streaming server is a service, not a child.* Version 1 started it from the Spoon and
  spoke to it over TCP; it held the microphone from start to exit, and a reload left servers
  behind still holding it. Now launchd runs one server, the Spoon connects over a WebSocket,
  and the microphone is open only around dictation. The server never exits on a client's
  account: a client leaving, a muted microphone, or a failed send ends the recording, not the
  server.
- *The microphone can change without a restart.* Each recording names its device.

* Tests

#+begin_src sh   :exports both
make test        # the server, with pytest; no Hammerspoon needed (about 90 s)
make test-quick  # the same without the 45 s real-time fixture
make test-live   # the Spoon in a running Hammerspoon 2 (about 3 minutes)
#+end_src

=tests/python/= tests =whisper_stream.py=: the audio helpers, the recorder with a stand-in
transport, the microphone opening and closing with a fake =sounddevice=, the WebSocket
transport with real clients, and the server as a real process. A WAV given with
=--test-file= stands in for the microphone: every recording plays it from the start, in real
time, and the end of the file ends the recording.

=tests/live/= drives the Spoon through =hs2=. Each script starts its own server with a test
file on a free port, points the Spoon at it, and puts the configuration and the clipboard
back when it finishes. =test_dictation_e2e.sh= also needs =whisper-server= on port 8080, and
=test_reconnect.sh= reloads the configuration and restarts the real server.

The fixtures are two recordings from the version 1 Spoon: =short.wav= (1 s) and =long.wav=
(43.5 s, cut into several chunks). Their =.txt= files are what version 1's transcriber
heard; the current =whisper-server= model hears only "happens." of =short.wav=, so the live
test compares a dictation with =whisper-server='s own transcription of the file.
