* hs_emacs-gt

Emacs from Hammerspoon 2: run elisp, forward keys that would otherwise never reach Emacs,
edit any application's text field in Emacs, show what Emacs has to say, and tell Emacs
how long the screen has been unlocked.

A port of two Hammerspoon 1 Spoons, =hs_emacs_helper= and =editWithEmacs=, merged into one.
Two Emacs Lisp files ship beside this readme:

| File                              | What it is for                                     |
|-----------------------------------+----------------------------------------------------|
| =hammerspoon.el=                  | Every call from Emacs to Hammerspoon 2.            |
| =hammerspoon-emacs-everywhere.el= | Editing a text field, through =emacs-everywhere=.  |

#+begin_src js   :exports both
const emacs = hs.loadSpoon("hs_emacs-gt")

emacs.executeAndRaise("(bookmark-bmenu-list)")
emacs.bindKey(["cmd", "ctrl"], "space")
emacs.message("saved")
#+end_src

The elisp is yours. Nothing in this Spoon names a function that is not part of Emacs, so
what to run belongs in your configuration:

#+begin_src js   :exports both
interactive.use("hs_emacs-gt", {
    commands: (interactive, emacs) => {
        interactive.define({
            name: "emacs-agenda",
            doc:  "Show the org agenda.",
            fn:   () => emacs.executeAndRaise("(dmg-agenda)")
        });
    }
});
#+end_src

* Requirements

- =emacsclient=, at =config.emacsClient=.
- A running Emacs server: =(server-start)=, or =emacs --daemon=.

=isRunning()= reports whether Emacs is running at all, and =execute()= reports a failed
=emacsclient= to the console and on screen.

* Running elisp

| Function                      | Does                                                |
|-------------------------------+-----------------------------------------------------|
| =execute(elisp, options)=     | Runs elisp. =options.raise= brings Emacs forward.   |
| =executeAndRaise(elisp)=      | The same, with =raise= set.                         |

Both return a promise resolving to whether =emacsclient= succeeded.

The elisp is passed to =emacsclient= as a single argument rather than through a shell, so
it needs no quoting — which matters, since elisp is made of parentheses, quotes and
backslashes.

Raising is best effort: the code runs whether or not Emacs comes forward.

=emacsclient= is run with =-n=, so it does not wait for a result. To read a value back,
call =hs.task.runAsync= directly without =-n=:

#+begin_src js   :exports both
hs.task.runAsync(emacs.config.emacsClient, ["-e", "(buffer-name)"])
    .then((r) => console.log(r.stdout))
#+end_src

* Bringing Emacs forward

| Function                  | Does                                                    |
|---------------------------+---------------------------------------------------------|
| =isRunning()=             | Whether Emacs is running.                               |
| =isFrontmost()=           | Whether Emacs is the frontmost application.             |
| =focus()=                 | Brings Emacs forward. Resolves to whether it worked.    |
| =waitForFrontmost(secs)=  | Resolves when Emacs is frontmost, or when time runs out. |

=focus()= uses =app.setFrontmost()= when Emacs is already running, which raises only
Emacs's main window and leaves its other frames where they are. =launchOrFocus= would bring
all of them in front of everything else, and is kept only for starting Emacs when it is not
running.

=waitForFrontmost= polls every =config.focusPollInterval= up to =config.focusTimeout=. The
Hammerspoon 1 version used a busy-wait, which stopped everything else in Hammerspoon,
timers included, for as long as it ran.

* Forwarding keys to Emacs

A chord bound here is sent on to Emacs instead of being acted on: Emacs is brought forward
and the same chord is typed into it. Use it for a chord macOS or another application would
otherwise swallow.

#+begin_src js   :exports both
const id = emacs.bindKey(["cmd", "ctrl"], "space")   // "cmd+ctrl+space"
emacs.toggleKey(id)          // off, then on again
emacs.toggleAllKeys(false)   // all off
emacs.keys()                 // [{id, enabled}]
#+end_src

| Function                    | Does                                                  |
|-----------------------------+-------------------------------------------------------|
| =bindKey(mods, key)=        | Forwards a chord. Returns its identifier.             |
| =toggleKey(id, enable)=     | Enables or disables one. Omit =enable= to toggle.     |
| =toggleAllKeys(enable)=     | The same for all of them.                             |
| =keys()=                    | Every forwarded key, as ={id, enabled}=.              |
| =unbindAll()=               | Releases them all.                                    |

The binding is disabled while the key is sent and re-enabled afterwards, so it does not
catch its own keystroke and recurse. When Emacs is not running the chord is sent to
whatever is in front instead, so the key is never simply swallowed.

* Messages

| Function              | Does                                                     |
|-----------------------+----------------------------------------------------------|
| =message(text, secs)= | Shows text on screen for a few seconds.                  |
| =messageHide()=       | Hides it now.                                            |
| =setStatus(text)=     | Shows text in the menu bar until it is cleared.          |
| =clearStatus()=       | Returns the menu bar to its resting icon.                |
| =windowAlert(text, secs)= | Shows text across the middle of the focused window.  |
| =windowAlertHide()=   | Removes every window alert still on screen.              |

The message is an =hs.canvas= in the upper left of the screen that holds the focused
window. It is rebuilt at each message rather than moved.

A window alert is as wide as the focused window and one line of large text high. Each
lasts its own duration, so several can be on screen at once. When no window has focus,
the text is shown as an ordinary =hs.ui.alert= instead. =windowAlertHide()= is there for
an alert that has been left on screen; it returns how many it removed.

The menu bar item is created by =start()= and shows =config.menubar.iconEmpty= when there
is nothing to report.

* Unlock time

=unlockSeconds()= returns the seconds since the screen was last unlocked. Emacs uses it to
leave time spent away from the computer out of how long it has been without a task.

Any of these =hs.power= events counts as an unlock, because which one macOS sends depends
on how the computer was locked or put to sleep: =screensDidUnlock=, =screensaverDidStop=,
=sessionDidBecomeActive=, =screensDidWake= and =systemDidWake=. The listeners are added by
=start()= and removed by =stop()=. Until the first unlock, the count starts from when the
Spoon was loaded.

* Configuration

| Setting             | Default                     | Meaning                              |
|---------------------+-----------------------------+--------------------------------------|
| =emacsClient=       | =/opt/homebrew/bin/emacsclient= | The client to run.               |
| =bundleID=          | =org.gnu.Emacs=             | Used to find and raise Emacs.        |
| =focusTimeout=      | 1                           | Seconds to wait for Emacs to appear. |
| =focusPollInterval= | 0.05                        | How often to look while waiting.     |
| =alertOnFailure=    | true                        | Show a failed emacsclient on screen. |

=config.message= holds =width=, =height=, =duration=, =font=, =textSize=, =textColor=,
=background= and =level=. =config.windowAlert= holds =duration=, =textSize=, =textColor=,
=background=, =cornerRadius= and =level=. =config.menubar= holds =enabled=, =iconEmpty= and =iconMessage=.

* Editing a text field in Emacs

Take the text of whatever field is focused, edit it in Emacs, and have the result pasted
back. This is the =editWithEmacs= half of the Spoon.

#+begin_src js   :exports both
emacs.editSelection()   // just the selection
emacs.editAll()         // the whole field
#+end_src

| Function                       | Does                                                    |
|--------------------------------+---------------------------------------------------------|
| =editSelection()=              | Edits the selection.                                    |
| =editAll()=                    | Edits the whole field.                                  |
| =beginEditing(everything)=     | What both call.                                         |
| =endEditing(id, everything)=   | Pastes the result back. Emacs calls this.               |
| =readFocusedText(everything)=  | The focused element's text, or null.                    |
| =windowInfo(id)=               | =x||y||w||h||application||title=.                       |

** What happens

1. The focused window is noted, and its identity written to =config.editing.infoFile=
   (=/tmp/emacs-everywhere.txt=) for Emacs to read.
2. The text is put on the pasteboard — through accessibility where the application
   exposes it, and by sending copy keystrokes where it does not.
3. Emacs is told to open an editing buffer, and brought forward.
4. When you finish, Emacs puts the text on the pasteboard and calls =endEditing= through
   the Hammerspoon command line. The original window is raised and the text pasted.

** Setting it up

Hammerspoon 2 needs its command line client installed, and =hs.ipc.start()= in your
configuration:

#+begin_src js   :exports both
hs.ipc.installBinary("/usr/local/bin")   // from the Hammerspoon console, once
#+end_src

Emacs needs =emacs-everywhere=, from [[https://github.com/dmgerman/emacs-everywhere][the dmgerman fork]]. The upstream package has
no way to add a system such as Hammerspoon from outside it. Put this Spoon's directory on
the =load-path=, and call the setup once =emacs-everywhere= is loaded:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/.config/Hammerspoon2/Spoons/hs_emacs-gt")
(require 'hammerspoon)

(use-package emacs-everywhere
  :config
  (require 'hammerspoon-emacs-everywhere)
  (hammerspoon-emacs-everywhere-setup))
#+end_src

=hammerspoon-emacs-everywhere-setup= does four things:

1. It adds Hammerspoon to =emacs-everywhere='s list of systems.
2. It makes =emacs-everywhere= treat macOS as Hammerspoon rather than as =quartz=.
3. It inserts the text with =yank=. The Spoon has already put the text on the pasteboard,
   so =emacs-everywhere= does not need to read the selection through =osascript=.
4. It binds =C-c C-c= to =hammerspoon-emacs-everywhere-finish=, which pastes the text back
   only when it has changed.

Any other way of ending the edit, such as =C-c C-k=, brings the original window forward
and pastes nothing.

=hammerspoon-emacs-everywhere-info-file= must name the same file as
=config.editing.infoFile=. Both default to =/tmp/emacs-everywhere.txt=.

An out-of-date client is worse than a missing one: it fails with a connection error that
looks like Hammerspoon being down. Reinstall it whenever Hammerspoon is updated.

** Differences from the Hammerspoon 1 Spoon

=hammerspoon.el= sends *JavaScript* rather than Lua, and pipes it to the client's standard
input, because the Hammerspoon 2 client has no =-c= option. Calls go to
=hs.spoons["hs_emacs-gt"]= rather than to =spoon.editWithEmacs=.

Pasting back is =window.focus()= followed by a delay of =config.editing.focusDelay= before
the keystrokes are sent, because the keystrokes go to whatever is frontmost when they are
sent and the activation is not instant.

** Calling Hammerspoon from Emacs

Emacs code calls these functions rather than writing JavaScript:

| Function                        | What it does                                         |
|---------------------------------+------------------------------------------------------|
| =hammerspoon-alert=             | shows an alert in the middle of the screen           |
| =hammerspoon-window-alert=      | shows an alert over the focused window               |
| =hammerspoon-message=           | shows text in the Spoon's own message display        |
| =hammerspoon-status=            | puts text in the Spoon's menu bar item               |
| =hammerspoon-status-clear=      | removes that text                                    |
| =hammerspoon-application-focus= | launches an application or brings it forward         |
| =hammerspoon-unlock-seconds=    | returns the seconds since the screen was unlocked    |

=hammerspoon-application-focus= takes a bundle ID, such as =net.ankiweb.anki=, because
=hs.application.launchOrFocus= in Hammerspoon 2 does not accept an application name.

Any other JavaScript goes through one of two functions:

- =hammerspoon-do= sends it and returns at once. The client is killed if it is still
  running after =hammerspoon-async-timeout= seconds (10 by default).
- =hammerspoon-execute= waits for the result and returns it as a string. It waits at most
  =hammerspoon-timeout= seconds (2 by default) and returns =nil= if no result arrives.

The client evaluates its input one line at a time, so every command has to be a single
line. =hammerspoon.el= quotes text as JSON, which writes a newline as =\n=.

** When Hammerspoon does not answer

After =hammerspoon-failure-threshold= failed calls in a row (3 by default), both functions
do nothing for =hammerspoon-cooldown= seconds (5 minutes by default), and Emacs shows a
warning when the pause begins. =M-x hammerspoon-reset= resumes the calls at once.

A command that throws is not counted as a failure, because Hammerspoon did answer.
=hammerspoon-execute= signals =hammerspoon-js-error= with the JavaScript message.
=hammerspoon-do= shows that message in the echo area.

The client prints =Connected to Hammerspoon 2= on standard output before every result,
and prints JavaScript errors there too. =hammerspoon.el= removes that line, and it tells a
result from an error by the client's exit status: 0 means success, 1 means the client
could not reach Hammerspoon 2, and 65 means the JavaScript threw.

** Running source blocks in Org

Source blocks in the language =hammerspoon= run in Hammerspoon 2, and are edited in
=js-mode=:

#+begin_example
,#+begin_src hammerspoon
hs.window.focusedWindow().application.title
,#+end_src
#+end_example

=:results value= returns the block's last expression. A string is returned as it is, and
anything else as JSON. =:results output= returns what the block passed to =console.log=;
outside a block, that goes only to the Hammerspoon console. Each =:var= is defined as a
global before the block runs. A block may run for =hammerspoon-babel-timeout= seconds
(30 by default).

The JavaScript backend that comes with Org, =ob-js=, cannot be used for this, for two
reasons:

1. It passes the block to the interpreter as a file name, and the client reads only
   standard input.
2. For =:results value=, it wraps the block in Node calls such as =require('process')=,
   which Hammerspoon 2 does not have.

Instead the whole block is sent as one line, passed as a string to a global =eval=. This
has two consequences. Definitions made with =var= or =function= remain for later blocks,
but those made with =const= or =let= do not. A block that returns a Promise returns the
Promise itself, because nothing waits for it.

** When an application will not give up its text

Some applications — terminals such as kitty, and anything drawing its own text — expose no
readable value through accessibility. The Spoon then puts
=config.editing.captureFailureSentinel= on the pasteboard and sends the copy keystrokes.
If the pasteboard has not changed afterwards, the application ignored them, and the
sentinel is what appears in Emacs. That is deliberate: it is better to see
=(application did not allow clipboard extraction)= than to silently edit whatever happened
to be on the pasteboard.
